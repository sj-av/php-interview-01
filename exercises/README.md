# Практика

Решения складывать в отдельные каталоги `01-sql`, `02-stock`, `03-orders-api`, `04-queue`, `05-review`. Не создавать код за пользователя, если задача дана ему для самостоятельного решения. Подсказки давать постепенно.

## 01. SQL: отчёт по заказам

Создай минимальную схему users/orders/order_items/products с PK, FK и обоснованными ограничениями. Добавь данные: пользователь без заказов, отменённый заказ, несколько заказов на границах периода, одинаковые даты.

Задания: сумма оплаченных заказов по пользователям; три самых дорогих заказа каждого пользователя; cursor pagination по created_at и id. Объясни модель хранения денег и трактовку границ периода/часового пояса. Для одного запроса предложи индекс и сравни планы на достаточно большом наборе данных.

Проверка: корректность на крайних случаях, отсутствие двойного подсчёта после JOIN, воспроизводимость SQL. EXPLAIN ANALYZE исполняет запрос — использовать учебную БД.

## 02. Остатки и конкуренция

Два покупателя пытаются приобрести последнюю единицу товара. Реализуй списание через PostgreSQL, запрети отрицательные остатки. Покажи поведение двух независимых соединений и отката транзакции. Разбери порядок блокировок при покупке нескольких товаров.

Проверка: только одна успешная покупка; при ошибке нет частичных изменений; конкурентный тест использует реальные отдельные соединения, а не последовательные mock-вызовы. Объясни выбранную изоляцию и обработку конфликтов.

## 03. Laravel API заказов

Реализуй создание заказа и чтение собственного заказа. Валидация входа, policy, серверный расчёт цены, транзакция и идемпотентность обязательны. Повтор с тем же ключом и тем же содержимым возвращает тот же результат; другое содержимое с тем же ключом вызывает явно определённый конфликт. Определи область действия и срок хранения ключа.

Проверка: успех, неверные данные, чужой заказ, недостаточный остаток, повтор после таймаута, одновременные повторы. Проверить SQL-запросы при выдаче списка заказов. Зафиксировать контракт ошибок и выбранные HTTP-коды.

## 04. Очередь и внешний эффект

Добавь событие создания заказа и фоновую отправку уведомления. Опиши точки падения между commit, публикацией, обработкой и ack. Сравни dispatch after commit и transactional outbox: какие сбои покрывает каждый вариант?

Проверка: retry/backoff, повторная доставка, наблюдаемость окончательных ошибок. Не заявлять exactly-once без доказательства для всей цепочки. Для внешней системы явно зафиксировать доступные механизмы идемпотентности.

## 05. Ревью и производительность

Возьми своё решение API. Найди риски безопасности, N+1, неоправданные зависимости и места сложного тестирования. Собери измерения до/после одной оптимизации; подготовь объяснение компромиссов.

Результат каждого задания: код/SQL, инструкция запуска, проверенные сценарии, ограничения и краткое объяснение решений. Версии окружения зафиксировать перед реализацией.
