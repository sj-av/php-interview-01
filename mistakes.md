# Ошибки и повторение

| ID | Тема / дата | Что было неверно | Корректная модель | Задача для повторения | Когда повторить | Результат |
|---|---|---|---|---|---|---|
| M01 | PHP coercion / 2026-11-11 | Ожидал аргумент 'hello' → int 0 в нестрогом режиме | Нестрогая проверка аргумента не равна явному касту: нечисловая строка для int вызывает TypeError | Новый пример со строковыми аргументами | Следующее занятие | Объяснено; применение после разбора не проверено |
| M02 | PHP strict return / 2026-11-11 | Ожидал return '42' → int у функции в строгом файле при вызове из нестрогого | Для return действует режим файла определения функции: здесь TypeError | Два файла: отдельно аргументы и return | После D02 или следующее занятие | Объяснено; требуется новый пример |
| M03 | CSV / 2026-11-11 | Допустил разбор каждой физической строки как отдельной записи при переносе внутри кавычек; предложил предварительно форматировать CSV | Перенос внутри кавычек допустим; границы записей определяет CSV-парсер, а не простое разбиение по строкам | Реализовать чтение CSV с многострочным полем | Следующее практическое задание по файлам | Объяснено; применение не проверено |
| M04 | Транзакции и платёж / 2026-11-11 | Сначала включил внешний платёж в транзакцию БД, затем предложил полностью отказаться от транзакций при работе через очередь | Внешний эффект не откатывается БД; локальное резервирование требует атомарной проверки и изменения; очередь этого не заменяет | Новый конкурентный сценарий с резервом и отказом внешнего сервиса | После разбора блокировки | Риски объяснены, самостоятельная реализация не получена |
| M05 | FOR UPDATE / 2026-11-11 | Назвал блокировку, но затруднился показать транзакцию, чтение, проверку и изменение | Блокирующее чтение, проверка доступного остатка и резервирование выполняются в одной транзакции | Самостоятельно реализовать аналогичный сценарий на другом примере | Следующая практика | Решение показано; после объяснения верно описал освобождение блокировки. Самостоятельная реализация не проверена |

| M06 | LEFT JOIN / 2026-11-11 | Фильтр правой таблицы в WHERE терял пользователей; OR status IS NULL не сохранял пользователей только с неподходящими заказами | Фильтровать подходящие заказы в ON или до LEFT JOIN; затем агрегировать и применять COALESCE | Новый пример с отсутствующими и неподходящими строками справа | Следующее занятие | С подсказками написал корректный ON; самостоятельно ещё не проверено |

Рекомендованный ритм повторения: через 1, 3, 7 и 14 дней после разбора, с поправкой на график. Это учебный ориентир, не настроенные уведомления. Закрывать ошибку после самостоятельного применения на новом примере, а не сразу после чтения объяснения.
