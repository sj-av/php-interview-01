# Программа

Порядок предварительный: после диагностики слабые обязательные темы идут первыми. Основные блоки 1–7: цель 2–3; остальные уточняются под вакансии. Оценка относится к проверенным подтемам, а не автоматически ко всему блоку.

| № | Блок | Темы | Практический критерий |
|---|---|---|---|
| 1 | PHP | Типы, strict_types, сравнения, null; ссылки и copy-on-write; массивы; closures; Throwable; generators; enums, readonly, attributes; Composer/autoload | Объяснить код и обработать большой поток данных с ограниченной памятью |
| 2 | ООП | Интерфейсы, traits, композиция, DI; SOLID; Strategy, Factory, Adapter, Decorator; границы ответственности | Рефакторинг сервиса с объяснением причин и цены абстракций |
| 3 | PostgreSQL и SQL | JOIN, агрегаты, HAVING, CTE, оконные функции; ограничения; индексы, составные и частичные; EXPLAIN (ANALYZE, BUFFERS); пагинация | Написать запрос и обосновать индекс на реальных данных |
| 4 | Конкурентный доступ | ACID, MVCC, изоляция PostgreSQL, row locks, deadlock; optimistic/pessimistic locking; retries; безопасные миграции | Доказать корректность списания остатков при двух транзакциях |
| 5 | Laravel | Lifecycle; container/providers; middleware; validation; policies; Eloquent relations, N+1, eager loading; scopes, casts; transactions; jobs/events; config cache | Проследить запрос и исправить N+1; вынести бизнес-логику из контроллера |
| 6 | HTTP и безопасность | Методы, коды, идемпотентность; sessions/cookies; authn/authz, CORS, CSRF, XSS, SQLi, SSRF; uploads; rate limit; API errors | Спроектировать защищённый API, проверяющий права на конкретный объект |
| 7 | Тестирование | PHPUnit; unit/integration/feature; mocks/stubs; фабрики и fixtures; реальные границы транзакций; PHPStan/Larastan; Composer lock | Проверить успех, ошибки, повтор запроса и реальные конкурентные изменения |
| 8 | Очереди и Redis | Ack, повторная доставка, retries/backoff, DLQ; идемпотентность; after-commit и outbox; TTL, invalidation, stampede | Разобрать падение worker после внешнего эффекта, но до ack |
| 9 | Эксплуатация | Nginx/PHP-FPM/OPcache; долгоживущие workers; Docker/Linux; CI/CD, rollback; logs/metrics/tracing; profiling | Локализовать рост p95 по измерениям и предложить безопасное исправление |
| 10 | Архитектура и интервью | Модульный монолит, распределённые транзакции, таймауты, согласованность; сложность алгоритмов; code review; рассказ об опыте | Защитить дизайн сервиса заказов и объяснить компромиссы |

## Этапы

1. Диагностика: вопросы и небольшая задача, без предварительного изучения ответов.
2. PHP/ООП и SQL/конкурентность: закрыть фундаментальные пробелы.
3. Laravel/HTTP/тестирование: упражнение API заказов.
4. Очереди/кеш/эксплуатация: добавить сценарии отказов.
5. Пробное интервью: вопросы, код, SQL, архитектура, рассказ о реальном опыте.

## Признаки готовности

- Два независимых задания по ключевой теме решены без подсказок, одно — после перерыва.
- Решения включают ошибки, повторы запросов и конкурентный доступ, где это применимо.
- Есть ясное объяснение выбранного подхода и хотя бы одной альтернативы.
- Есть 3 истории из реального опыта: сложный баг, улучшение, компромисс. Не выдумывать опыт; при отсутствии использовать учебные задачи и честно называть их учебными.
- Пробное интервью показывает конкретные оставшиеся пробелы; отсутствие пробелов не гарантирует оффер.
