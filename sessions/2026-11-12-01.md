## Продолжение: outbox и доставка

- Проверено: внешний эффект при retry, атомарность pending, неопределённость SMTP, HTTP-идемпотентность, два получателя, timeout/400/429, next_try_at, конкурентный захват, срок processing и устаревший владелец.
- Самостоятельно: повтор внешнего эффекта и отправка после коммита; стабильные ключи и разные ключи получателей; повтор timeout с тем же ключом; потеря при sent до SMTP (после объяснения ограничений); поле next_try_at и условие времени. Эти конкретные ответы — 2.
- С подсказками: pending внутри транзакции (сначала после неё); отдельные строки outbox предложил наставник, пользователь обосновал удобство; короткая транзакция processing вместо HTTP под блокировкой; восстановление после падения и идентификатор владельца получены последовательными направленными вопросами — 1 для целого механизма.
- Ошибки: M13 продолжен; все 4xx считал постоянными, после контрпримера выделил 429; catch предложил для падения процесса, после уточнения предложил истекающий захват. Реальный код/тесты не запускались.
- Коррекция наставника: пользователь прав, owner_id с новым UUID для следующей последовательной обработки достаточно. Повторный захват одним асинхронным процессом до завершения старого callback — введённое наставником условие; не считать непониманием пользователя. Код этого искусственного сценария показан, не запускался.
- Решение: по просьбе пользователя завершить текущий устный этап и перейти к планам PostgreSQL; общая реализация перевода/outbox не объявляется проверенной. Оценки относятся только к указанным подтемам.
